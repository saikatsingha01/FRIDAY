# KI-008 — Nondeterministic Understanding memory-store misclassification derails a math answer

Date: 2026-08-07

## Symptom

Voice message (fresh session):

> "x squared plus 5x plus 6 equals 0 solve for x"

Routed correctly to `llama3.1:8b` (capability `mathematics`, Category Lookup,
no fallback), but FRIDAY answered with a clarification about "waking up at
5:30" instead of solving the equation. Re-asking the same question in another
fresh session produced the correct answer (x = −2, x = −3). Nondeterministic.

## Root Cause

- The Model Router is NOT at fault: both sessions routed `mathematics` →
  `llama3.1:8b` exactly as specified.
- The Understanding LLM (llama3.2:3b) occasionally emits a spurious
  `memory_operation: "store"` with a bogus `canonical_fact` (its own
  quadratic-formula write-up) for a solve-equation message. When it does, the
  memory-conflict gate flags `needs_confirmation` against unrelated existing
  memories (e.g. `I wake up at 5:30` / `I wake up at 8:00` in the real store),
  and the response generator turns that into a clarification question instead
  of answering the math.
- When the same message happens to classify with `memory_operation: null`, the
  conflict gate is skipped and the solve is answered correctly.

## Why it is deferred

- The failure is Understanding-layer nondeterminism on the `memory_operation`
  field (same class as KI-007 but in a different field), not a Phase 4 router
  bug. The router did exactly what it was supposed to in both sessions.
- Failure is safe: no wrong memory write and no crash — an availability /
  quality gap, not a correctness gap.
- No code was changed for this issue.

## Reproduction

1. Have conflicting personal memories in the store (e.g. "I wake up at 5:30"
   and "I wake up at 8:00").
2. Ask "x squared plus 5x plus 6 equals 0 solve for x" repeatedly in fresh
   sessions.
3. Intermittently FRIDAY asks "which is correct, 5:30 or the math?" instead of
   solving. When the classifier emits `memory_operation: null`, it answers
   correctly.

## Future approach

- Add the exact voice wording ("x squared plus 5x plus 6 equals 0 solve for x"
  — a reordering of the worked example currently in the prompt) as a worked
  example with explicit `memory_operation: null`. Worked examples are the only
  lever that has reliably changed the small model's structured output in this
  project; rule/forbidden-variant lines alone do not (see KI-007).
- Longer term: gate `memory_operation` on the goal — a solve/calculate goal
  should never carry a store operation — enforced at the Understanding output
  boundary, not in the router.
