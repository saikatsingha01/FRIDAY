# KI-004 — Phase 2.7 Review: Fixed Now, Deferred Later

Date: 2026-08-03

A systematic review pass of Phase 2.7 (Smart Memory Recall) was done against
the 7 reported issues. Issues in the current phase were fixed and verified.
Issues belonging to later phases are documented here with the future approach,
per the "fix only the current phase" rule.

---

## 1. Fixed in Phase 2.7 (verified)

### 1.1 Test 1 — "Do you remember what educational course I am currently doing?"

Root causes (two independent failures):

1. The stored education fact was categorized as `device` because
   `detect_category` matched "computer" inside "Computer Science Engineering"
   before it reached any education keyword.
2. `MemoryQuery` had no `education` category mapping, so an education query
   fell back to `["preference"]` — FRIDAY only searched preferences.

Fixes:

- `src/memory/memory_manager.py`
  - Added `education` to `detect_category` (before `device`) with study/course/
    degree/university keywords.
  - Added `education: 9` to `calculate_importance`.
- `src/memory/memory_query_builder.py`
  - Added `education` to `CATEGORY_MAP`, `CATEGORY_KEYWORDS`, and the
    profile-category list.
  - Added a `query_text` field used ONLY for semantic embedding scoring
    (never parsed).
- `src/memory/memory_retriever.py`
  - Added embedding-based semantic scoring with a 0.5 similarity floor and a
    0.7 ramp, so cross-vocabulary recall works ("educational course" vs a
    stored "B.Tech") without dragging in unrelated memories.
  - High-value-category boost now only ranks memories that already matched
    category or keyword; it can no longer create relevance on its own.
- `src/memory/memory_evaluator.py`
  - Added study/education personal patterns ("i study", "i'm studying",
    "my degree", ...) so neutral identity facts like "I study B.Tech
    Computer Science Engineering" are reliably stored (previously the LLM
    sometimes dropped "am", leaving "I study ...", which scored 0).

Verified results (education fact stored as `education`, importance 9):

- "I am studying B.Tech Computer Science Engineering" -> stored.
- "Do you remember what educational course I am currently doing?" ->
  returns the education memory first; food/game/Darjeeling memories excluded.
- "What degree am I pursuing right now?" -> returns the education memory
  (semantic recall, no shared vocabulary).
- "What is my favorite food?" -> food memory first, education memory excluded.

### 1.2 Regression (Phase A / Phase B) — all still passing

- Understanding: "I study btag" surfaces uncertainty and asks to clarify;
  "I study B.Tech" stores cleanly; world-knowledge questions bypass memory.
- Planning: BTech/electromagnetism/France are knowledge answers (no planning);
  the study-plan request plans with 3 steps.

## 2. Deferred — Phase 2.8 (Write Quality / Context Depth / Validation)

### 2.1 Transient, low-value statements must never enter long-term memory

Reported: "okay then lets gonna copy it" was stored as "I want to copy
something".

Current safeguard (verified): the write gate already rejects it —
`evaluate_memory("I want to copy something")` returns
`should_remember=False`, so `auto_remember` returns False and nothing is
stored. The response asks for clarification instead of inventing context.

Future approach (Phase 2.8):

- LLM-aware importance: let the understanding LLM judge lasting relevance
  instead of keyword heuristics alone.
- Ephemeral vs permanent memory: transient intents (copy, paste, open,
  one-time tasks) stay in short-term context and never persist.
- Require at least one durable attribute (identity/education/preference/
  project/device/relationship) before a write is accepted.

### 2.2 Response grounding / invented links

Reported: after the copy statement, FRIDAY invented a link to the user's
B.Tech course.

Current state: the copy fact is no longer stored, so the invented link is far
less likely. Residual risk remains when a `general`-category query falls back
to every category and unrelated memories are shown to the LLM; a smaller model
may still fabricate a connection.

Future approach (Phase 2.8 / Phase 4):

- Tighten the `general` category fallback in `CATEGORY_MAP` and cap results
  for low-signal queries.
- Ask the LLM to reference the specific memory it uses ("from your memory of
  ..."), making fabrication visible.
- Confidence-aware response layer (Phase 4): answer only from facts above the
  recall confidence threshold.

## 3. Deferred — Phase 3 (Entity Extraction / Planner Stabilization)

- Entity extraction is LLM-faithful but not enforced (no NER layer); a missed
  entity means a recall query loses its strongest keyword. Future: dedicated
  extraction model, entity->memory index.
- Planner parsing was hardened in Phase B (clean/code-fence/prose/
  trailing-comma/single-quote/unquoted/smart-quote, garbage->None) and needs a
  unit-test suite and step-validation before being exposed further.

---

## 4. Deferred — Phase 4 (Reasoning / Personality / Uncertainty)

- Confidence-aware responses: the pipeline tracks understanding confidence but
  the LLM does not always reflect it in tone.
- Uncertainty surfacing currently only happens for memory writes; extend to
  general answers.
- Personality layer (tone, humor, directness) remains a layer on top of the
  honest-core rules.

---

## 5. Deferred — Phase 5 (World Knowledge Separation)

- A world-knowledge prompt branch already exists (Phase A): direct answers,
  "do not look in the user's memories". Full separation still needs a
  knowledge store distinct from personal memory, provenance, and an
  explicit "I don't know" policy.
- Reported: "Don't you know about the BTech course?" correctly answered from
  general knowledge without touching personal memory (verified).
