# KI-011 — Launch-turn reply occasionally re-states the immediately preceding answer (RECENT CONVERSATION bleed)

Date: 2026-08-08

## Symptom

Live user test, two consecutive turns in the same session:

1. "what is the price of the nvidia rtx 5070" → FRIDAY answers correctly
   (e.g. ~$549).
2. "launch chrome" → Chrome launches and FRIDAY says "Chrome is launched",
   but **also repeats the RTX 5070 price**, which the user did not ask about.

Intermittent — most launch turns are clean ("Chrome is open.").

## Root Cause

The previous exchange is carried verbatim into the launch turn's prompt. The
prompt assembles `RECENT CONVERSATION` from the session buffer
(`src/core/context_manager.py`, `MAX_CONTEXT = 15`, formatted as
`User: ... / FRIDAY: ...` lines in `src/ai/prompt_builder.py:_format_context`),
so the GPU-price question AND FRIDAY's factual answer are both present in the
launch turn's prompt.

The response model is `llama3.2:1b` (device category → FAST_CHAT). The prompt's
stale-context guard is a **soft instruction** ("The TOOL RESULTS are the only
facts for this turn. Ignore ENTITIES MENTIONED and everything in RECENT
CONVERSATION — never carry them into this reply."). A 1b model does not
reliably follow it: on some turns it treats the most recent factual content in
RECENT CONVERSATION as something to include, and repeats the price after (or
with) the launch confirmation. It is purely model nondeterminism — the
routing/execution layers were correct (Chrome did launch; the ToolResult was
the launch success).

Offline reproduction with the current code: 5 runs of the exact shape (GPU
Q&A as context + successful Chrome launch + real LLM) all returned only
"Chrome is open." — consistent with the user seeing it as an occasional,
rare echo, not a reliable failure.

## Why it is deferred

- User-classified as a minor issue; the launch itself is correct and the extra
  sentence is a quality/availability gap, not a wrong action.
- The instruction-level suppression is already as strong as a prompt can be;
  the residual is the small response model. Fixing it reliably requires
  structural change (trim RECENT CONVERSATION for launch/tool turns, or use a
  stronger model for tool-result narration), which the user asked not to make
  now.
- No code was changed for this issue.

## Reproduction

1. Ask FRIDAY any factual question and let it answer (e.g. "what is the price
   of the nvidia rtx 5070").
2. Immediately say "launch chrome" (or any app).
3. Occasionally FRIDAY confirms the launch and then repeats the prior answer.

## Future approach

- For tool/launch turns, either (a) omit or heavily truncate RECENT
  CONVERSATION when the tool results are self-contained (a launch needs none
  of the prior turn), or (b) route tool-result narration to a stronger model
  (DEFAULT_CHAT / REASONING tier). Both are structural changes outside the
  current scope.
- Longer term: the KI-007/KI-009 schema-validated Understanding layer plus a
  stable response-tier mapping for tool turns removes the class of
  "small model repeats context it was told to ignore" residuals.
