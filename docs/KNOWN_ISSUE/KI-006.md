# KI-006 — Politeness/acknowledgment message mid-plan derails into the active plan

Date: 2026-08-06

## Symptom

While a plan was active ("learn python from code with harry youtube channel",
a Python-learn plan), the user said:

> "its okay thank you"

FRIDAY re-answered the Python goal instead of simply acknowledging. The
final response was generated from an executed plan whose steps referenced
Python/"Code with Harry" (content copied from the active plan), and memory
was also retrieved (5 memories) for a message that carries no information.

## Root Cause (confirmed by read-only probe, 2026-08-06)

The politeness message reached the planner and was merged into the active
plan. Contributing chain, each link fails open for social/acknowledgment text:

1. **Triage false negative (fast-path miss).** `"its okay thank you"` scores
   below the gratitude exemplar threshold (0.85): extra words ("its okay")
   dilute the embedding. Probe: `'thank you' -> gratitude (1.000)` but
   `"its okay thank you"` -> trivial `None`, and `'its okay' -> affirmation
   (0.864)` alone is also below a safe social-match line. So the message
   falls through to the full Understanding LLM. (By design this is a
   fail-open single extra call — the real damage happens downstream.)

2. **Off-taxonomy intent from Understanding.** The probe returned
   `intent: "acknowledgment"` for `"its okay thank you"`. The contract's
   allowed values are question/command/request/correction/feedback/
   conversation/end_session — "acknowledgment" is not one of them. The LLM
   also invented an out-of-list `category` ("politeness") in the live trace
   and set `goal: remember_information` (a real goal value) for a message
   that stores nothing.

3. **Continuity gate passes.** `_continues_active_plan` skips only
   `{conversation, greeting}`. `"acknowledgment"` (and the taxonomy-legal
   but also-unskipped `feedback`) are not in the skip set, so with an active
   plan the gate returns continuation -> `use_planning = True`
   (`continuity_only`). A message with zero goal content is routed into the
   planner purely because it is short, social, and a plan happens to exist.

4. **Planner over-continues / goal-bias.** Handed a politeness message next
   to an active plan, the planner either merges it into the active plan or
   emits a new goal ("acknowledge") whose steps inherit the active plan's
   content (`is_goal_request` is biased TRUE, `continues_active_plan`
   defaults TRUE while a plan exists).

5. **`plan_detour` backstop does not fire.** In `src/core/brain.py`,
   `plan_detour` only catches `semantic.goal in DETOUR_GOALS`
   (`{"retrieve_information", "amusement"}`) or `not is_goal_request`.
   `goal="remember_information"` is a "real" goal value that also appears
   on actual goal messages, and the planner reports `is_goal_request=True`,
   so the detour is skipped and the plan executes -> the response LLM
   re-answers the Python goal from the polluted plan + retrieved context.

## Why it is deferred

- The trigger is an interaction of three unreliable outputs (triage score,
  Understanding intent/goal, planner goal judgment) each with its own
  correct-but-improvable bias. There is no single deterministic signal that
  reliably separates "acknowledgment" from a genuine short continuation of a
  plan (`"ok go on"`, `"please continue"`, `"yes tell me"` are all 2-4 words,
  no goal vocabulary, same position in the conversation).
- The failure is safe: no wrong memory write, no active-plan corruption that
  survives (the executed plan is a derived object, `_active_plan` still holds
  the original on the merged path). It is a correctness/UX gap, not a data
  corruption one.
- Fixing it properly belongs to Layer 3 (Standardized Response Pipeline /
  intent-resolution), where short no-goal utterances get an explicit
  "acknowledge-and-stay" response class before the planner is consulted —
  not to another keyword list or another planner-prompt rule.

## Reproduction

1. Start a plan: "i want to learn python from code with harry youtube channel".
2. After the plan is set, say "its okay thank you".
3. FRIDAY re-answers the Python goal instead of a simple acknowledgement.

## Future approach (Layer 3 — Standardized Response Pipeline)

- Add an explicit non-goal response class: short social/acknowledgment
  utterances are answered before the planner is consulted (acknowledge the
  sentiment, keep the active plan intact, no LLM plan).
- Tighten the continuity gate: skip `feedback` (and off-taxonomy
  acknowledgment-like intents) in addition to `{conversation, greeting}`;
  a no-goal message must never flip `use_planning` on continuity alone.
- Make `_is_short_followup` require evidence the message *acts on the plan*
  (imperative, affirmative, question about the plan), not just shortness +
  recent context.
- Add politeness/acknowledgment exemplars to the triage fast-path so common
  forms like "its okay thank you" hit the zero-LLM template answer instead
  of the full pipeline.
