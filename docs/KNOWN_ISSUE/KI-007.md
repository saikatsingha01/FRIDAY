# KI-007 — Understanding LLM emits off-enum `capability` variants; router falls back gracefully

Date: 2026-08-07

## Symptom

The Understanding LLM (llama3.2:3b) sometimes labels the new `capability`
field with words that are NOT in the 22-category enum. Observed variants:
`explaining`, `information`, `problem-solving`, `debugging`, `workout`,
`memory_operation`. The Model Router treats any non-enum value as
`general`/`DEFAULT_CHAT` (llama3.2:3b) — safe, but a message that should have
used the 8b reasoning model or the 7b coding model can silently downgrade to
3b when the classifier invents a variant.

## Root Cause

- `capability` is a brand-new field added in Phase 4. Small models follow
  structured output examples strongly but are noisy when no near example
  exists; when in doubt they paraphrase the task into a new word instead of
  picking from the enum.
- The exact-message worked examples are the strongest lever: adding the three
  originally-mislabeled messages as examples (`explain how a capacitor
  works` → science, `give me a 30 day workout schedule` → planning, `can you
  help me fix a bug in my python script` → programming) moved all three from
  off-enum to correct on-enum. Relocating the math example to the most recent
  prompt position (and changing its `goal` from `solve_problem` to
  `calculate`, which leaked the string "problem-solving" into the capability
  slot) fixed the `problem-solving` variant.
- Residual nondeterminism remains: the classifier can emit a different
  off-enum variant at runtime even for a message that has a worked example.

## Why it is deferred

- The router is explicitly a pure dictionary lookup with NO keyword matching or
  hidden logic, so it must never try to "repair" an off-enum value. Its only
  universal response is the `general` fallback, which is correct and safe.
- Improving classifier consistency is a prompt/examples task in the
  Understanding layer, and the ROADMAP already lists "Stable Understanding
  (so category output is consistent, not noisy)" as a dependency of this
  phase. The failure mode is graceful (correct model, no crash, no wrong
  write).

## Reproduction

Run the Phase 4 stress harness repeatedly. Most runs pass 64/64; a noisy run
shows an e2e case routed to `llama3.2:3b` instead of the expected
`llama3.1:8b` / `qwen2.5-coder:7b`, always accompanied by a `MODEL ROUTER`
block with `Reason: Unknown category '<variant>', falling back to general`.

## Future approach

- Keep adding exact-message worked examples for any newly-observed variant
  (cheapest reliable lever for small models).
- Consider a post-parse enum validator in the Understanding layer that
  re-asks / coerces ONLY at the classifier output boundary (not in the
  router), or a stronger structured-output constraint (JSON-schema enum
  format) when the interface supports it.
