# KI-005 — Compound message: dismissal clause + recall question ends the session

Date: 2026-08-05

## Symptom

Voice message:

> "let's stop discussing about that and please tell me what's my favorite movie?"

FRIDAY responded:

> "Shutting down."

and the session ended (TTS confirmed "Shutting down."). The correct behavior is:
the topic-dismissal clause should be acknowledged (no write), and the trailing
recall question answered from memory.

## Root Cause

- "let's stop discussing about that" is a topic-dismissal clause. The
  topic-dismissal / end-session micro-classifier is a YES/NO LLM call that is
  intentionally conservative, but compound messages expose its limit: when the
  dismissal clause is fused with a real question in one utterance, the
  classifier labels the whole message as a session/topic end.
- The message is a single utterance carrying TWO intents (dismiss the topic AND
  recall a memory). The current pipeline resolves the compound to the
  session-end path instead of the question path, so the recall question is never
  asked of memory and the session stops.

## Why it is deferred

- It is a compound-intent resolution problem, not a memory problem. It belongs
  to the Response Pipeline / intent-resolution phase (Layer 3), where one
  utterance may be decomposed into multiple intent steps.
- The failure is safe (no wrong write, no false memory); it is an availability
  gap, not a correctness gap. No code was changed for this issue.

## Reproduction

1. Store a favorite-movie memory (e.g. "my favorite movie is interstellar").
2. Say "let's stop discussing about that and please tell me what's my favorite movie?"
3. FRIDAY shuts down instead of answering.

## Future approach (Layer 3 — Standardized Response Pipeline)

- Decompose compound utterances into ordered intent steps (dismiss-topic →
  answer-question) before routing.
- Give the end-session / topic-dismissal classifier a hard rule: a clause that
  also requests information (question mark / interrogative follow-up) is never a
  bare session end; the question intent wins.
- Only the response/execution layer should decide "session over" once no
  pending intent remains.
