DI-003 — Natural Language Understanding

Priority: High

Current limitation:

Friday understands only predefined sentence structures.

Future solution:

Use an LLM or local NLP model capable of understanding user intent rather than exact wording.

Expected improvements:

Handle paraphrased questions.
Understand requests naturally.
Distinguish statements, questions and commands.
Better conversational ability.

-----------------------------------------------------------------------------------------------------------------------------------------------

Engineering Decisions

Decision:

Avoid spending significant development time improving the temporary keyword-based intent system.

Reason:

The architecture already allows the intent detector to be replaced by an AI-based solution in the future without affecting the rest of the project.

Focus should remain on long-term features such as:

Speech Recognition
Vision
Memory
Security
Tool Usage
Autonomy

---

Progress notes (2026-08-17/18)

Free-form phrasing is still the deferred durable fix, but the deterministic
layers now absorb part of the gap for the filesystem domain:

- Compound spoken numbers are parsed deterministically ("chapter twenty
  one" -> "chapter 21", "two hundred five" -> "205"; `_canonical_tokens` /
  `_parse_number_run` in `src/utils/path_resolver.py`).
- Single-word folder names survive even when the Understanding model drops
  every entity (`_raw_filesystem_reference` single-token recovery in
  `src/core/tool_router.py`).
- Unmistakable filesystem phrasing ("whats inside X folder", "list my
  downloads", "its inside the c lab folder") is routed by the user's own
  words via `_fs_decisive()` even when the model classified the turn as a
  web search (KI-015).

The AI-based intent/NLU replacement remains the planned end-state; the
deterministic gates above are universal rescues, not per-phrase rules.
